# 应用名单与放大优先级

验证日期：2026-11-11。

原先名为“应用名单”的区域只保存 `quitOnCloseApplications`，用于关闭窗口时退出应用。放大红绿灯的扫描、鼠标事件、窗口恢复等路径只检查全局 `enabled`，因此名单无法控制放大。名单还被嵌套在 `quitOnCloseEnabled` 条件下，关闭退出功能就会隐藏名单。

## 当前行为

应用名单独立显示在全局放大开关下方。每个应用按 Bundle ID 匹配，支持三个放大选项：

| 应用设置 | 全局开启 | 全局关闭 |
| --- | --- | --- |
| 跟随全局 | 放大 | 不放大 |
| 开启 | 放大 | 放大 |
| 关闭 | 不放大 | 不放大 |

没有添加到名单的应用遵循全局设置。移除应用或选择“跟随全局”后恢复当前全局默认。规则保存后立即刷新，无需重启应用。

“添加应用”菜单可以直接选择正在运行的应用，也可通过“选择其他应用…”打开附着在设置窗口上的应用包选择器。重复添加相同 Bundle ID 不会重置已有规则。

每个条目另有“加入关闭时退出应用”选项，沿用原有全局退出开关的控制关系。新添加的应用默认不加入退出名单，避免仅为关闭放大而添加 UU 远程时，意外改变其关闭行为。旧退出名单自动迁移，放大选项保持“跟随全局”；原有退出功能的启用状态不变。旧名单的存储键仍保存退出成员，便于回退旧版本。

## 运行时处理

`Preferences.overlaysEnabled(bundleIdentifier:)` 统一解析放大优先级。应用筛选、覆盖层创建、窗口移动和缩放、最小化恢复、鼠标触发、位置同步，以及 Dock 最小化的覆盖层分支均使用这个结果。

全局关闭时，只要存在单独开启的应用，窗口跟踪和指针处理仍可运行。单独关闭某应用时，在扫描其他应用之前先隐藏并移除其现有覆盖层；玻璃、原生按钮遮罩及动画随覆盖层一起撤下。退出应用的窗口观察独立保留。

## 验证

- 107 项 Swift 测试通过，包括新增的双向优先级、大小写匹配、持久化、移除和继承、旧名单迁移、退出功能隔离，以及修改规则后发送刷新通知。
- 发布构建通过，安装包完成 ad-hoc 签名验证；安装后的可执行文件与构建产物 SHA-256 一致。
- 使用真实运行的 UU 远程和 Finder，通过本地测试程序调用实际 `WindowTracker` 并检查覆盖层对象，获得下列结果。测试使用独立临时设置域。

本机最终保存 `com.netease.uuremote` 的放大规则为“关闭”，全局开关保留原有关闭状态。上述检查验证规则和覆盖层生命周期；未操作远程会话内部的全屏控件。全屏和非标准标题栏的原有能力范围没有扩展。

应用包选择器的目录选择开关见 [Apple NSOpenPanel 文档](https://developer.apple.com/documentation/appkit/nsopenpanel/canchoosedirectories)。本次通过界面完成的是“正在运行的应用”添加路径。
